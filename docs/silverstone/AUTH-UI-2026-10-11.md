# App-open through PIN: silver / AMOLED design pass

Date: 11 October 2026. Working branch: `Development`.
Baseline: `8f9c86d1437f8e76b617de3dbcbfb2b448c9db20`.

## Direction and scope

Extend the approved sub-agent design to launch, restoration, login, password-recovery request/confirmation, PIN creation/confirmation, returning-user PIN, forgotten PIN and connection retry. Reuse the existing silver `#C4C7CB` and AMOLED `#000000` tokens, Inter/Manrope families and exact post-login vector mark. Plain surfaces, outline controls, generous spacing, 48-point minimum actions; no auth bottom navigation or invented capabilities.

The native splash now uses monochrome mark assets and per-platform light/dark settings. The JavaScript splash and font-loading stage use the same visual language. Native splash changes require rebuilding the APK/dev client; Metro reload alone is insufficient. Existing launcher icon is retained.

Loaders use an indeterminate moving track, with a still reduced-motion fallback. Inline buttons show action-specific busy text. The global loader uses a restrained surface over a scrim, blocks touches and hides underlying content from accessibility while visible. Loader animation stops on unmount and reacts to system motion preferences.

## Behavior retained and guarded

- Existing API client, auth provider, credential authority, stored sessions and local PIN storage remain unchanged.
- First-time PIN creation requires matching confirmation before saving. A mismatch retains the chosen first PIN, offers retry and an explicit start-over action. Storage failure does not unlock.
- PIN entry checks the existing lockout; checks repeat on foreground and before verification/biometrics. Same existing three-attempt / thirty-minute policy. Numeric entry and asynchronous submissions are guarded against overlapping requests.
- Failed sign-in/recovery/reauthentication retains input and displays the actual error. Recovery success remains neutral about account existence.
- Normal in-app Sign Out still locks the account; Not-name still requires confirmation and invokes real logout.
- Pending/restricted account routing and registration wizard are preserved.
- The new password-recovery screen calls the existing recovery request endpoint. A mobile reset-link callback / new-password completion flow is still outstanding and is not simulated here.
- English and Swahili UI copy is supplied; human language acceptance remains open.
